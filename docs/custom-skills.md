# 自创技能·积木系统 设计稿

目标：让用户在 UI 里用**可复用的效果积木**拼出自创角色技能，且**真在引擎里生效**（不是只喂 AI 的人设文本）。
分两期落地；本文档是设计底稿，随实现更新。

---

## 一、积木模型

一个自创技能 = `触发时机` + `目标规则` + `一个或多个效果块`（可按目标阵营分支）。

### 效果块（第一期）
| 块 | 作用 | 复用/新增 |
|---|---|---|
| `inspect` 查验 | 得知目标阵营（狼/好人） | 复用预言家 |
| `protect` 守护 | 目标当晚免疫狼刀 | 复用守卫 |
| `poison` 毒杀 | 目标当晚死亡 | 复用女巫毒 |
| `blockKill` 封刀 | 触发则**当晚全体狼无法击杀** | 新增 |
| `muteSkill` 封技能 | 目标**当晚的夜间主动技失效** | 新增 |
| `delayedDeath` 缓死 | 见白猫；改死亡时机 | 新增 |

### 效果块（第二期）
| 块 | 作用 |
|---|---|
| `grantSkill` 授予技能 | 给某玩家临时获得【查验/毒/盾】之一（奇迹商人） |
| `reflect` 反弹 | 打到指定目标的查验/守护/毒，改为落到施法神职自己身上（蚀时狼妃） |
| `lynchImmune` 首放逐免疫 | 首次被投票放逐时翻牌免疫、不死（愚者） |
| `shieldTransfer` 一次性可转移护盾 | 护他人挡一次夜刀，闲置则转护己；触发即消耗（愚者） |

### 修饰
- `startRound`：第 N 晚起才可用（子狐=2）
- `uses`：`nightly`（每晚）/ `once`（一次性，触发后消耗）
- `canTargetSelf`：能否选自己（默认否）
- `feedback`：施法者是否收到私密反馈（如"你媚惑的X是狼"）
- `byTargetTeam`：按目标阵营分支不同效果（子狐核心）

## 二、样板角色

### 子狐 🦊（第一期）
- 阵营：神职（好人）
- 技能「媚惑」：`startRound=2`，`uses=nightly`，每晚选 1 人（不可选自己）
  - 目标是**狼阵营** → `blockKill`（当晚全狼禁刀）
  - 目标是**好人阵营** → `muteSkill`（目标当晚夜间技能失效）
  - `feedback=on`：私密告知子狐"你媚惑的X是狼/好人"
- 「封技能」范围：只封**当晚夜间主动技**（预言家查/女巫药/守卫守）；被动与死亡技（猎人枪/狼王咬）不封；白天技（骑士决斗）不封。

### 白猫 🐈‍⬛（第一期）
- 技能「缓死」（被动）：被**任意方式**判出局的瞬间不死，挂缓死标记、**继续正常存活**（可发言/投票/用技能），并**立即公开身份**（翻牌亮明"白猫·缓死中"）。
- 死亡时机：**下一轮的同一种阶段**才真正死亡。
  - 🌙 夜里被刀 → 下一个夜晚结算死
  - ☀️ 白天被投/枪杀/自爆 → 下一个白天投票阶段死
- 细则：缓死期间**算活人**（可拖延胜负判定）；缓死期间再受致命伤忽略；被白狼王自爆带走也享受缓死。

### 奇迹商人 🎪（第二期）
指定一名幸运儿赐予【查验/毒/盾】三选一；幸运儿若是狼 → 不给技能且当场出局。
**待定**：三技能由商人选/随机/幸运儿自选；赐予为当晚一次性还是持续；商人每晚可赐还是一次性。

### 愚者 🃏（第二期）
- 阵营：好人。**白天免疫 与 夜间护盾共用"一次保命"，任一先触发则全部技能消失**。
- 【白天】首次被**投票放逐** → 翻牌、免疫此放逐（不死）、失去所有技能。
- 【夜间】每晚指定一人挂护盾，替其抵消一次夜间致命伤；若被护者当晚没挨刀/被别人救活（盾没用上）→ 护盾自动转护愚者自己当晚生效；成功挡下一次伤害后失去所有技能。
- 默认细则：盾是一次性资源、留到触发为止；"被别人救活"不算触发；免疫后仍可投票；白天免疫仅对投票放逐（自爆/枪等照死）。**待定**：这些默认是否调整。

### 蚀时狼妃 🌒（第二期）
- 阵营：**狼阵营**（狼队反弹型神职）
- 当晚选一名玩家 X，凡查验/守护/毒打到 X 的都反弹到施法神职自己身上；触发一次后失去封锁。
- **待定**：反弹是"任意一种挡一次"还是"三种各一次"。

## 三、引擎接入思路（低改动、集中式）

核心：**不逐个改几十处按 role.id 的分发**，而是把自创技能的产出收进 `S.nightData.customFx`，在 `resolveNight` 的**最前面**做一次预处理，按积木改动局面：

1. **夜间收集**：给"带自创技能的角色"加一段通用夜间提问 → 写入 `S.nightData.customFx = [{caster, blocks, target, ...}]`。
2. **resolveNight 预处理**（在结算刀口/毒/查验之前）：
   - `blockKill` → 置 `S.nightData._noKill=true`；刀口结算最前面加一句判断。
   - `muteSkill` → 调 `suppressNightSkill(targetId)`：按目标 role.id 清掉其写入的 nightData 贡献（seer/guard/witch…），一个集中函数搞定。
   - `inspect/protect/poison` → 复用既有字段。
3. **缓死**：`killPlayer` 检测到目标带 `delayedDeath` 且首次出局 → 不真正结算，改为登记 `pendingDeath={phase, dieAtRound}` + 立即翻牌公开；在每个夜间结算 / 白天投票阶段开头检查到期者，届时才真死。
4. **胜负**：缓死者在真死前一律计入存活。

单测覆盖积木纯逻辑；真实 AI 对局平衡由作者用 key 实测后微调。

## 四、实现状态（随代码更新）

第一期 5 个样板角色**全部已接入引擎**（不止喂 AI 文本，真在夜间/结算中生效）。实现上没有搭"通用积木引擎"，而是沿用代码库既有的「每角色独立 `nightData` 字段 + 独立 `NightActions.xxx` 函数 + resolveNight 定点结算」模式（更贴合现有几十处按 `role.id` 分发的写法、改动更集中、更不易出错）。角色经 `reg()` 注册后即可在自定义局里直接选。

| 角色 | id | 阵营 | 状态 |
|---|---|---|---|
| 白猫 🐈‍⬛ | `whitecat` | 好人 | ✅ 缓死 |
| 子狐 🦊 | `fox` | 好人 | ✅ 媚惑（第2夜起：狼→禁刀 / 好人→封技） |
| 愚者 🃏 | `fool` | 好人 | ✅ 首放逐免疫 + 可转移护盾（共用一次保命） |
| 奇迹商人 🎪 | `merchant` | 好人 | ✅ 赐予（盾/查验/毒；幸运儿是狼→当场出局） |
| 蚀时狼妃 🌒 | `wolfconcubine` | 狼 | ✅ 反弹锁定（查/守/毒打到X→反噬施法神职） |

### 接入要点
- **子狐·封技能**：预言家在其夜间行动源头拦截跳过；守卫/女巫/魔术师在 `applyCustomNightFx()`（resolveNight 最前）清空贡献，**女巫解药/毒药自动退还**。封刀=`foxBlockKill`，在刀口结算最前拦截（覆盖机械狼破盾刀）。
- **蚀时狼妃·反弹**：静默重定向到施法者自己（施法者不知情，仍以为作用在 X 上）。预言家在源头即时反弹，守卫守护/女巫毒在 `applyCustomNightFx()` 反弹；**首个命中 X 的神职触发，仅一次**。
- **愚者·护盾**：做成 resolveNight 里对 `deaths` 数组的一次"救回后处理"——护住的人挨刀则救他，闲置则盾自动转护愚者自己；成功挡下一次即 `_foolUsed=true`、失去全部技能（含白天免疫）。首放逐免疫在 `killPlayer` 顶部拦截（仅 `cause==='vote'`，自爆/枪/审判照死）。
- **奇迹商人·赐予**：盾=被赐者获一次性免夜死（同愚者的救回后处理）；查验/毒=被赐者获一次性夜间技，**次夜起**由 `NightActions.grantedSkill` 主动使用；幸运儿是狼→`cause='merchant'` 当场出局。

### 已按最简一致版本定夺的"待定"项（待作者实测后微调）
- **奇迹商人**：三礼物由**商人自己选**；赐予为**一次性**（盾=当晚、查验/毒=次夜一次）；商人**每晚**可赐。
- **愚者**：盾一次性、留到触发；"被别人救活"不算触发（本实现里护盾只从最终死亡名单救人，天然满足）；免疫后仍可投票；白天免疫仅对投票放逐。
- **蚀时狼妃**：反弹为"任意一种挡一次"（当晚首个命中 X 的查/守/毒触发，本夜只反弹这一发）。**这是每晚循环技**——"仅一次"指当晚只反弹一发，不是整局一次性；`_concubineTriggered` 每夜随 `S.nightData` 重置，狼妃每晚可重新锁定、再反弹一次。AI 面向文案已明确此点，避免被理解成"用一次就废"。**反弹来源已统一**：内置预言家/守卫/女巫、积木自创角色的查验/守护/毒、以及奇迹商人赐予出去的查验/毒，凡打到 X 的都算——与"凡查验/守护/毒打到 X 的都反弹"设定一致（`reflectInspectSubject` 处理查验、`reflectEffectTarget` 处理守护/毒落点）。
